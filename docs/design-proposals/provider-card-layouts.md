# ProviderCard 卡内排版设计方案（4 方案）

> 任务：t_698a43c9（以卡评论 #1043 终稿为准，覆盖卡体与前序评论）
> 对象：Provider 卡片**内部的排版** —— 多窗口的 QuotaMeter 实例在卡片里怎么摆才好看。
> 纯设计文档：供用户选型，选型后再开实现卡。
>
> 对应 mock 渲染：QuotaGallery「Provider 卡片」段 S1-S4（feat/theme-glass，截图见卡评论）。

## 设计前提（硬约束）

- **QuotaMeter 已定稿不改**：一个实例 = 一个窗口的额度展示（标题/重置/进度条/用量四元素 + pct/state/unit 参数）。所有方案的窗口行一律用 **QuotaMeter 当前默认排版（layout=row，t_23800bd4 主页同规）**；duo 等排版切换等用户后续拍板，本设计不定案。
- **ProviderCard = 组合件**：一张卡 = 一个 provider = 头部（BrandLogo + provider 名称 + StatusDot + 徽章文字，D-005/D-039 拖拽把手保留）+ 窗口区（按 metrics 循环渲染 QuotaMeter，一窗一个）。
- 4 方案差异**只在卡内排版**（窗口区组织/分组/间距/对齐/层级、头部与窗口区关系），不是 QuotaMeter 本体改造。
- 8px / tokens.css / D-016 三态；e2e DOM 契约（`.progress` / `.progress-fill[data-health]` / `role=progressbar` / `data-testid=provider-card`）零破；setup_hint 授权状态必须承载（保留 t_52e3a7fb 列式修复）。
- 窗口按时间窗升序排列（5h → 周 → 月，§6.3），最紧窗标红只标不排序（S2 的「风险上抬」是**摘要直呈**而非抽离重排）。

## 共用结构（四方案一致）

```
┌────────────────────────────────┐ 360px 面板内宽 ~336px
│ [◆≡] Kimi-Code #1     [●] 偏低 │ ← head: BrandLogo(拖把手) + 名称 + StatusDot + 徽章
│  ……窗口区（方案差异所在）……      │
└────────────────────────────────┘
```

头部 = `BrandLogo`(D-039 拖把手载体) + `card-name` + `StatusDot`(8px, `data-health`) + `statusBadge()` 文字；异常卡（auth_expired/error/stale）共用同一骨架，body 换 AbnormalBody 同构槽（黄灯/红字 + setup_hint 授权面板），不渲染假窗口行（§2.1）。

## 方案 1 · 基准竖排列表式（基准对照）

```
┌────────────────────────────────┐
│ [◆≡] Kimi-Code #1     [●] 偏低 │
│ 5 小时窗  ████████████░░░  960/1200 次 (80%) │
│                        ~3.2 小时后重置        │
│ ──────────────────────────────────────────── │ ← 1px 分隔线(--border)
│ 周  窗    ████░░░░░░░░░░░  1200/6000 次 (20%)│
│                        ~5.8 天后重置          │
└────────────────────────────────┘
```

- **排版逻辑**：窗口区 = 每窗一个 QuotaMeter 竖排堆叠；窗间 1px 分隔线（`--border`）+ 8px 节奏（`--space-8` 上距 + `--space-8` 内距）；头部与窗口区主从分明。
- **适用场景/取舍**：窗口数 **1-4 最佳**；5-6 窗纵向冗长但扫描仍稳。最中性无惊喜；现状最接近，用户认知零成本。取舍：多窗时卡总高随窗数线性增长，无压缩手段。
- **token 引用**：`.card` 容器 padding `--space-8/--space-12`；窗间 `border-top: 1px solid var(--border)` + `margin/padding-top: var(--space-8)`；卡片 bg `--bg-elev`、border `--border`、圆角 `--radius-12`。
- **实现边界**：**复用现有 ProviderCard 壳**（`.card`/`.card-head` 不动），仅窗口区容器化（新增 `.card-windows` 类，BarsTemplate 的 `.bar-row` 列表迁入），零结构重构；e2e 契约不变。

## 方案 2 · 头部融合式（风险上抬）

```
┌────────────────────────────────┐
│ [◆≡] Kimi-Code #1     [●] 偏低 │
│ ┌──────────────────────────────┐ ← 警示色带(--warn 10% 底 + 30% 边)
│ │ ⚠ 最紧窗                     │
│ │ 5 小时窗 ████████████░░  960/1200 次 (80%) │
│ │                    ~3.2 小时后重置         │
│ └──────────────────────────────┘
│ 5 小时窗  ████████████░░░  960/1200 次 (80%) │ ← 窗口区完整列表(时间窗升序)
│                        ~3.2 小时后重置        │
│ ──────────────────────────────────────────── │
│ 周  窗    ████░░░░░░░░░░░  1200/6000 次 (20%)│
│                        ~5.8 天后重置          │
└────────────────────────────────┘
```

- **排版逻辑**：最紧窗（remaining 最小）在头部下方以**警示色带**摘要直呈，风险一瞥可见；窗口区仍按时间窗升序完整列表（最紧窗**不抽离不排序**，§6.3 契约保留——摘要带是「标红」的强化，不是重排）。
- **适用场景/取舍**：窗口数 **1-6 均适用**，尤其多窗场景避免风险沉没（5 窗卡里 5h 窗快耗尽仍沉在列表中部的问题）。取舍：风险信息重复一次（摘要带 + 列表原行），头部密度上升；ok 态卡警示带可隐藏（无风险时不占高度）。
- **token 引用**：警示带 `background: color-mix(in srgb, var(--warn) 10%, transparent)` + `border: 1px solid color-mix(in srgb, var(--warn) 30%, transparent)`（D-016 三态 token 零硬编码）；圆角 `--radius`；padding `--space-4/--space-8`；带下距 `--space-8`。
- **实现边界**：**复用现有 ProviderCard 壳** + 新增 `.card-tightest-strip` 容器（head 下方、窗口区上方插槽）；tightest 选择复用 `metricHealth`/remaining 比例计算（纯函数，可测试）；窗口区与 S1 同构。

## 方案 3 · 分区卡片式（周期分区）

```
┌────────────────────────────────┐
│ [◆≡] Kimi-Code #1     [●] 偏低 │
│ 短周期                           ← 分区标签(--font-10 dim)
│ 5 小时窗  ████████████░░░  960/1200 次 (80%) │
│                        ~3.2 小时后重置        │
│ ──────────────────────────────────────────── │ ← 区间分隔线(8px 间距)
│ 长周期                           ← 分区标签
│ 周  窗    ████░░░░░░░░░░░  1200/6000 次 (20%)│
│                        ~5.8 天后重置          │
└────────────────────────────────┘
```

- **排版逻辑**：窗口区按周期分组——**短周期**（5h/日窗，急迫消耗）与**长周期**（周/月+，预算基线）各立分区标签（`--font-10` dim），区间 8px + 1px 分隔线，组内紧凑 4px（`--space-4`）。分区本身就是「这是什么性质的窗」的认知锚。
- **适用场景/取舍**：窗口数 **4-6 时层级最清晰**（多窗场景分组是稀缺信息架构）；1-2 窗时分区标签冗余（单分区可自动隐藏标签）。取舍：分区是固定二分（短/长），跨周期模糊的窗（如 3 日窗）归属规则需另定。
- **token 引用**：分区标签 `--font-10` + `var(--fg-dim)`；区间 `margin-top: var(--space-8)` + `border-top: 1px solid var(--border)`；组内 gap `--space-4`。
- **实现边界**：**复用现有 ProviderCard 壳** + 窗口区按 span 分组渲染（`zoneOf(key)` 纯函数，可单测）；无分区数据时（单窗）退化为 S1 形态；结构增量最小。

## 方案 4 · 紧凑密度式（行距收敛）

```
┌────────────────────────────────┐
│ [◆≡] Kimi-Code #1     [●] 偏低 │
│ 5 小时窗  ████████████░░░  960/1200 次 (80%) │
│                        ~3.2 小时后重置        │
│ 周  窗    ████░░░░░░░░░░░  1200/6000 次 (20%)│ ← ok 窗无重置行
└────────────────────────────────┘
```

- **排版逻辑**：取消窗间分隔线，行距压到 4px（`--space-4`），**ok（健康）窗不渲染重置行**（状态色已表达健康，重置是辅助信息；`resetText` 缺省即 QuotaMeter 不渲染该 slot，契约不破）→ 每个健康窗省一行。
- **适用场景/取舍**：窗口数 **5-6 时总高省 ~20-30%**（多窗卡不再纵向爆炸）；取舍：窗间分界靠间距语气弱于分隔线，首扫需适应；ok 窗丢「何时重置」信息（hover tooltip 的 micro 排版已有四元素含重置，可补位）。
- **token 引用**：窗间 `margin-top: var(--space-4)`（无 border）；健康判定复用 `metricHealth()`（剩余 >30% = ok 阈值 D-022）。
- **实现边界**：**纯 CSS modifier + 条件 prop**（`resetText` 缺省不渲染），零结构重构；QuotaMeter 四元素 DOM 顺序契约不破。

## 横向对比

| 方案 | 核心手法 | 窗口数最佳区间 | 信息层级 | 结构增量 | 风险一瞥 |
|------|---------|---------------|---------|---------|---------|
| S1 基准竖排 | 分隔线+8px 节奏 | 1-4 | 头部>窗口区，主从分明 | 容器化零重构 | 弱（靠列表内标红） |
| S2 头部融合 | 最紧窗警示色带 | 1-6 | 风险带>头部>窗口区 | +1 插槽 | **最强** |
| S3 分区卡片 | 周期分区标签 | 4-6 | 分区>窗口 | +zone 分组纯函数 | 中（分区助定位） |
| S4 紧凑密度 | 去分隔线+ok 藏重置 | 5-6 | 密度优先 | 纯 CSS/条件 prop | 弱 |

## 建议

**S1 为稳妥基准**（实现边界最小、与现状形态一致）；**S2 推荐作为默认首选**（token-wallet 是「配额风险看板」，最紧窗上抬直接服务 glanceability，§6.3 契约不破）；S3 适合多窗重度用户（4+ 窗 provider 增多后再启用）；S4 作为「密度偏好」备选（若用户嫌卡太长）。

异常卡（auth_expired/setup_hint 等）四方案共用同一骨架，不参与排版选型。
