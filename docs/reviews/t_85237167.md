## BLOCKING 修改项（2 项）

### B1. 方案 B 头部「综合态文字」固定为「综合健康」— 与文档 ASCII 及方案卖点矛盾

- 位置: `packages/app/src/components/ProviderCardVariants.tsx` CardHead `mode="expanded"` 分支
  （`{abnormal ? statusBadge(p) : t("quota.card2Health")}`），i18n `card2Health: "综合健康"`。
- 实况: mock kimi 卡 health=warn（黄灯），头部显示 **黄灯 +「综合健康」**——黄灯=偏低，文字却写"综合健康"，
  用户会误读为健康。文档 v2 L54 ASCII 画的是 `● 偏低`；L67 卖点「综合态一行让『健康/偏低/告急』一瞥可读」。
- 要求: 状态文字改为按 health 变化（`healthLabel(health)` 或 `statusBadge(p)` 同源，kimi →「偏低」），
  与 A/C/D 头部徽章一致；`card2Health` i18n 键删除或改为动态语义。**这是 B 方案的核心卖点，固定文案=卖点失效。**

### B2. 方案 D 头部最紧窗用量数字出现两次 — 与文档 ASCII 单次不符，自相矛盾

- 位置: `ProviderCardVariants.tsx` VariantD — CardHead `highlight` 渲染 headline
  （「5 小时窗 960 / 1200 requests」）+ 独立 `qcard2-trigger--head` pill 再显「960 / 1200 requests」。
- 实况: DOM 实测 head text = `Kimi-Code #1 | 5 小时窗 | 960 / 1200 requests | 偏低` +
  最右 pill `960 / 1200 requests` = **同一数字两处**。文档 L97 ASCII 只有一处 `5h 960/1200`，无独立 pill。
- 要求: 头部数字只保留一处——headline 承担数字展示，trigger 区不再渲染第二个 formatUsage
  （hover 锚点可为透明的 head 区域或紧凑 ⓘ，与 B 的 trigger 风格对齐）；或去掉 headline 由 trigger 承担，二选一收敛。
  **D 方案卖点本是「避免重复」（行内 hideUsage），头部自己重复=自相矛盾。**
