## 修改项

### 1. [packages/core/src/channels/aliyun-bailian.ts:113(及 healthCheck :203)] BLOCKING — 真实 bl 下 auth_expired 分类结构性失效

**复现**(本机 bl 1.18.0 + 1.18.1 双版本实测, 干净 HOME 复现):
`bl usage token-plan --output json` 未登录 → **exit=3, 错误 JSON 写 stderr, stdout 空**。
stream 分离实测: stdout 空; stderr = `{"error":{"code":3,"message":"No console access token found.","hint":"Run \`bl auth login --console\`."}}`。

而 `BailianTokenPlanAdapter.fetchSnapshot` 只判 `isAuthExpiredBody(res.stdout)`:
stdout 恒空 → 判别永不命中 → 落入 `res.code !== 0` 通用 error 分支 → 产出
`error_message: "bl usage 失败(exit=3)"`, **无 setup_hint**。

经 runCommandFetch 默认 executor(真实 spawn, 生产同路径)实测输出:
`status: error, error_message: "bl usage 失败(exit=3)", setup_hint: undefined, alerts: []`

**影响**: bl 已装但 console 未登录(最常见的真实状态, 含用户 Windows 首装后未登录) →
用户拿到红色通用 error 卡「采集失败」, 而非 D-041 契约承诺的黄灯 auth_expired 卡 +
`bl auth login --console` setup_hint。auth_expired 健康语义整体失效。

**根因**: 单测 fixture(bailian.test.ts:91)把 AUTH_EXPIRED body 放在 **stdout**,
与真实 bl 行为(写 stderr)不符, 测试假设掩盖了缺陷。D-041 契约只说「exit=3 + body」未定 stream, 实现取了错的 stream。

**要求**:
1. fetchSnapshot/healthCheck 的 auth-expired 判别改为同时覆盖 stdout+stderr
   (如 `isAuthExpiredBody(res.stdout + res.stderr)` 或双 stream 检查), stdout 保留(兼容其他平台/版本差异)
2. 单测补真实形态 fixture: exit=3 + body 在 stderr → 断言 auth_expired + setup_hint;
   保留原 stdout fixture(两 stream 都要能判)
3. 在 bl 已装未登录的机器上跑 runCommandFetch 默认 executor 取证 auth_expired(本机即可复现)
