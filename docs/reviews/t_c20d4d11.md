### B1 [app.css .card-del-zone/.card-del-btn] 删除钮真实用户无法点击（hit-test 死锁）
位置: packages/app/src/app.css L392-450（本 commit c1d380f 的修订 H 让位增强）
现象: `.card-del-zone` z-index:3 + pointer-events:auto 常驻，盖在 `.card-del-btn`(z-index:2) 之上；
让位契约 `.card:has(.card-del-btn:hover)` 要求按钮先收到 :hover 才关 zone 的 pointer-events ——
但 zone 在上、按钮永远收不到 hover → :has() 永不触发 → zone 永不释放 → 点按钮 = 点 zone(无 handler)。
实测证据（Playwright 真实鼠标，非 force）:
  - mouse.move 到按钮中心 → elementFromPoint = `DIV.card-del-zone`（不是按钮）
  - 真实 mouse down/up 点按钮中心 → 删除确认气泡不出现 → 删除流程无法触发
这正是 e2e 5 个失败的同一根因（`locator.hover: ... intercepts pointer events`），
worker 用 `force: true` 绕过 Playwright actionability 掩盖了真实交互缺陷，
自审说「实际 UI 正常, 手工点击无问题」与实测矛盾。
要求: 修掉死锁 —— zone 让位不能依赖「按钮先被 hover」（按钮物理上在 zone 下面）；
建议 zone 设 pointer-events:none 且由兄弟/父级选择器控制可见性，
或让按钮浮出(z-index 高于 zone)后再接点击。修完必须删掉 e2e 的 force:true 恢复真实点击断言。
验收契约: 任务书「e2e 全绿」+ D-038 卡内删除真实可用。
